### 1.2 已对齐的规范要点（来自 spec.md）

| 模块 | 关键决策 |
|------|---------|
| **账号体系** | `users` 统一表，`role='parent'/'child'` 区分；**无 children 表**；**无 current_child 字段** |
| **孩子切换** | 前端 `localStorage` 记录 `current_child_id`；后端接口通过 `?child_id=` 参数识别 |
| **积分兑换** | **无审核流程**，点击兑换即扣积分 + 扣库存 + 生成记录 |
| **手动加减积分** | 本质 = 创建一条 `status=3(已完成)` 的 tasks 记录 + 可选上传凭证照片 |
| **成长相册** | 数据源 = tasks 表中 `photo IS NOT NULL AND (status IN (2,3) OR (status=3 AND points!=0))` |
| **认证** | JWT Token，`POST /auth/register`、`POST /auth/login` |
| **数据隔离** | 所有查询自动加 `family_id = 当前用户家庭ID` |

### 1.3 技术栈确认

- **后端**：Go 1.22+，Gin Web Framework，GORM + SQLite，golang-jwt/jwt/v5，bcrypt
- **前端**：React 18 + TypeScript + Vite + Tailwind CSS 3 + Zustand + React Router v7 + Recharts + Lucide
- **文件存储**：本地 `backend/uploads/` 目录 + `/uploads/xxx` 静态路由
- **数据库文件**：`backend/data/growpocket.db`

## 三、详细实施计划

### 阶段 1：后端基础架构

**文件 & 模块**

| 文件 | 作用 |
|------|------|
| `backend/go.mod` | `module growpocket`；依赖 gin/gorm/sqlite/jwt/bcrypt |
| `backend/cmd/main.go` | 启动入口：加载配置 → 初始化数据库 → 注册路由 → 启动 |
| `backend/internal/config/config.go` | 配置结构体 + 环境变量加载（JWT_SECRET, DB_PATH, UPLOAD_DIR, PORT） |
| `backend/internal/model/*.go` | 6 个 GORM 模型（User, Family, Task, Transaction, RedeemItem, Redeem） |
| `backend/internal/database/database.go` | GORM 初始化 + AutoMigrate |
| `backend/internal/middleware/*.go` | CORS, JWT Auth（解析 Token → 注入 user_id/family_id/nickname 到 Context）, 统一响应 |
| `backend/internal/handler/response.go` | 统一响应格式 `{ code, message, data }` + 错误常量 |
| `backend/pkg/util/*.go` | 密码哈希（bcrypt）、JWT 生成/解析、分页工具、日期工具 |

**关键实现要点**

1. `User` 模型必须包含 `role` 字段（字符串 `parent`/`child`）和 `balance`（int，默认 0）。
2. GORM 的 AutoMigrate 在应用启动时调用，确保首次运行自动建表。
3. JWT Payload 中包含 `user_id`, `family_id`, `nickname`；有效期 2 小时。
4. `uploads/` 通过 Gin 的 `r.Static("/uploads", "./uploads")` 暴露。
5. 所有需要登录的 API 路由挂在 `/api` 组下，并应用 `JWTAuth` 中间件。

---

### 阶段 2：认证模块

**文件**：`backend/internal/handler/auth.go` + `backend/internal/service/auth.go`

**关键流程**

1. **POST /api/auth/register**
   - 请求：`{ nickname, password }`
   - 步骤：验证 nickname 唯一性 → 密码 bcrypt 哈希 → 创建 `family`（名称 = `nickname + "家"`）→ 创建 `user(role='parent')`，`family_id`=新家庭 ID → 生成 JWT → 返回 `{ token, user: {id, nickname, family_id, family_name} }`

2. **POST /api/auth/login**
   - 请求：`{ nickname, password }`
   - 步骤：查询 `users WHERE role='parent' AND nickname=?` → bcrypt 验证密码 → 生成 JWT → 返回同上

---

### 阶段 3：孩子档案管理

**文件**：`backend/internal/handler/children.go` + `backend/internal/service/children.go`

**关键接口**

| 方法 | 路径 | 关键逻辑 |
|------|------|---------|
| POST | `/api/children` | 插入 users（role='child', balance=0, family_id=当前家庭） |
| GET | `/api/children` | `SELECT * FROM users WHERE family_id=? AND role='child'` |
| GET | `/api/children/:id` | 详情 + 验证 id 属于当前家庭 |
| PUT | `/api/children/:id` | 更新 nickname / gender / birthday / avatar |
| DELETE | `/api/children/:id` | 删除（有 tasks/transactions/redeems 关联时前端提示，但允许强制删除） |
| PUT | `/api/family/name` | `UPDATE families SET name=? WHERE id=?` |

**要点**：**不提供 `/api/children/:id/switch` 接口**（前端 localStorage 自管理）。

---

### 阶段 4：任务管理（核心模块）

**文件**：`backend/internal/handler/tasks.go` + `backend/internal/service/tasks.go`

**关键接口**

| 方法 | 路径 | 关键逻辑 |
|------|------|---------|
| POST | `/api/tasks` | 插入 tasks；如果请求中 status=3 且 points!=0 → 直接走「奖惩任务」路径（创建任务 + 生成 transaction + 更新 child.balance — 全部在一个事务里） |
| GET | `/api/tasks` | `WHERE family_id=?` + 可选 `?status=&child_id=` + 分页 |
| GET | `/api/tasks/:id` | 详情 + 家庭校验 |
| PUT | `/api/tasks/:id` | 仅 status ≤ 2 可编辑 |
| DELETE | `/api/tasks/:id` | 仅 status ≤ 2 可删除 |
| PUT | `/api/tasks/:id/submit` | 上传照片 → 写入 `photo` 字段 → status 1→2 |
| PUT | `/api/tasks/:id/review` | 事务：approved=true → status=3 → 生成 transaction(type=income) → `users.balance += points`；approved=false → status=4 |

**照片上传实现**：Multipart form file → 生成随机文件名（uuid + 原扩展名）→ 保存到 `backend/uploads/` → 返回 `/uploads/filename` 作为 photo 字段。

**事务保证**：`PUT /tasks/:id/review` 的积分结算和 `POST /tasks` 创建奖惩任务时都必须使用 `db.Transaction()`，保证任务状态更新 + 积分更新 + transaction 记录要么全部成功要么全部回滚。

---

### 阶段 5：积分管理

**文件**：`backend/internal/handler/score.go` + `backend/internal/service/score.go`

| 方法 | 路径 | 关键逻辑 |
|------|------|---------|
| GET | `/api/score/balance?child_id=` | `SELECT balance FROM users WHERE id=? AND role='child'` |
| GET | `/api/score/history?child_id=&page=&page_size=` | 列表 + 分页；返回 `amount, type, reason, balance_after, created_at` |
| POST | `/api/score/add` | `{ child_id, title, description, points, photo(可空) }` → **本质调用 TaskService.CreateRewardTask(points>0)** → 创建 `status=3` 任务 + 生成 transaction + 原子更新 balance |
| POST | `/api/score/deduct` | 同上，但 points 需传入正数，后端内部取负值；余额不足时返回 400 |
| GET | `/api/score/trend?child_id=&days=7` | 从 transactions 聚合，返回最近 N 天每天结束时的余额；若某天无交易则沿用前一日余额；第一日前默认 0 |

---

### 阶段 6：兑换商城

**文件**：`backend/internal/handler/redeem.go` + `backend/internal/service/redeem.go`

| 方法 | 路径 | 关键逻辑 |
|------|------|---------|
| POST | `/api/redeem/items` | 创建商品（name/points/category, 可选 description/image/stock）；stock 不传则 = -1（无限） |
| GET | `/api/redeem/items?category=&page=&page_size=` | 商品列表 + 分页；`stock=-1` 一律显示 |
| GET | `/api/redeem/items/:id` | 详情 |
| PUT | `/api/redeem/items/:id` | 更新商品信息 |
| DELETE | `/api/redeem/items/:id` | 逻辑删除 = 设置 stock=0 |
| POST | `/api/redeems` | **单事务完成 3 步**：① `SELECT balance FROM users WHERE id=child_id FOR UPDATE` 校验余额 ≥ item.points ② 若 stock≠-1 则 `UPDATE items SET stock=stock-1 WHERE id=item_id AND stock>0` 并发校验 ③ 扣余额 + 生成 redeem 记录 + 生成 expense transaction；任一步失败全部回滚 |
| GET | `/api/redeems?child_id=&page=&page_size=` | 列表；JOIN items 拿到商品名和图片 |

---

### 阶段 7：成长记录

**文件**：`backend/internal/handler/growth.go` + `backend/internal/service/growth.go`

| 方法 | 路径 | 关键逻辑 |
|------|------|---------|
| GET | `/api/growth/album?child_id=&page=&page_size=` | 从 tasks 表查询 `photo IS NOT NULL AND (status IN (2,3) OR (status=3 AND points!=0))` → 返回 `task_id, task_title, photo, points, created_at` |
| GET | `/api/growth/timeline?child_id=&days=30` | 三类事件聚合：① tasks status=3（标题：title，±积分） ② redeems（标题：item.name，-积分） ③ transactions related_type='manual' 的额外记录（reason + ±amount） → 按日期分组排序 |

## 六、关键风险与处理

| 风险 | 影响 | 处理方案 |
|------|------|---------|
| **并发兑换**：同一家长快速点击「兑换」两次导致扣双倍积分或库存负数 | 积分扣减错误 / 库存超卖 | 后端在 `POST /api/redeems` 中使用数据库事务 + `SELECT ... FOR UPDATE`（SQLite 中用事务 + UPDATE ... WHERE balance>=x 返回 rows_affected 判断） |
| **手动减积分余额不足** | 余额变负 | `POST /score/deduct` 事务中先校验 `balance >= points`，不足返回 400 |
| **照片上传大小/格式** | 后端存储大文件 / 非图片文件 | 前端限制 ≤ 5MB；后端再次校验文件头（jpg/png/gif） |
| **首次登录没有孩子** | 首页所有数据为空 | 首页引导「添加第一个孩子」；所有需要 child_id 的 API 前端兜底：当无 current child 时先调用 `addChild` 引导 |
| **日期/时区** | JWT 过期时间 / 积分趋势图日期不一致 | 全部使用 UTC；前端根据本地时区展示 |
| **SQLite 不支持真正的并发** | 高并发下性能问题 | MVP 阶段可接受；后续如需多家庭可切换到 MySQL / PostgreSQL |
