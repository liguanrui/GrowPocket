# 童劳童得 - 智能音箱集成功能 PRD

## Overview
- **Summary**: 为童劳童得系统添加智能音箱集成功能，使儿童可以通过语音交互方式查询分数、查看任务、了解活动并提交任务，解决儿童没有设备难以参与系统的问题。
- **Purpose**: 通过智能音箱语音交互，降低儿童使用门槛，让孩子更便捷地参与家务任务和积分系统。
- **Target Users**: 6-12岁儿童（主要用户）、家长（监督和审核）

## Goals
- 支持儿童通过智能音箱查询个人积分
- 支持儿童通过智能音箱查询今日待办家务
- 支持儿童通过智能音箱查询正在招募的活动
- 支持儿童通过智能音箱提交任务成果（进入待审核状态）
- 通过声纹识别确保用户身份安全

## Non-Goals (Out of Scope)
- 不支持通过音箱进行积分扣减操作
- 不支持通过音箱进行兑换申请
- 不支持通过音箱进行家庭管理操作
- 不支持音箱端的图片/视频展示功能

## Background & Context
- 现有系统是一个微信小程序，家长发布任务，孩子完成任务获得积分，积分可兑换奖励
- 部分儿童没有智能手机或平板电脑，难以参与系统
- 智能音箱普及率高，语音交互更适合儿童使用
- 声纹识别可提供基本的用户身份验证

## Functional Requirements
- **FR-1**: 声纹识别用户身份 - 系统通过声纹识别验证儿童身份
- **FR-2**: 积分查询 - 儿童可通过语音查询自己的当前积分
- **FR-3**: 任务查询 - 儿童可通过语音查询今日待办家务任务
- **FR-4**: 活动查询 - 儿童可通过语音查询正在招募的活动
- **FR-5**: 任务提交 - 儿童可通过语音提交任务成果（进入待审核状态）

## Non-Functional Requirements
- **NFR-1**: 语音响应时间 < 3秒
- **NFR-2**: 声纹识别准确率 > 95%
- **NFR-3**: 仅支持查询类操作，写数据操作需人工审核确认
- **NFR-4**: 语音交互采用儿童友好的语言风格

## Constraints
- **Technical**: 需要对接主流智能音箱平台（如天猫精灵、小爱同学、小度等）
- **Business**: 确保儿童隐私安全，声纹数据加密存储
- **Dependencies**: 依赖现有后端API接口

## Multi-Platform Adaptation Strategy (多音箱平台适配方案)

### 1. 架构设计原则
- **统一接口层**: 设计统一的语音技能接口，屏蔽各平台差异
- **适配器模式**: 为每个音箱平台创建适配器，将平台特定协议转换为统一格式
- **配置化管理**: 通过配置文件管理各平台的差异配置

### 2. 主流平台适配策略

| 平台 | 接入方式 | 语音唤醒词 | 特殊适配要求 |
|------|----------|------------|--------------|
| 天猫精灵 | 阿里IoT开放平台 | "天猫精灵，打开童劳童得" | 支持天猫精灵特有语音指令格式 |
| 小爱同学 | 小米AI开放平台 | "小爱同学，打开童劳童得" | 支持米家生态联动 |
| 小度 | 百度DuerOS开放平台 | "小度小度，打开童劳童得" | 支持百度语音识别特性 |
| 华为小艺 | 华为HiAI开放平台 | "小艺小艺，打开童劳童得" | 支持华为生态设备联动 |

### 4. 平台差异化处理

| 差异类型 | 处理策略 |
|----------|----------|
| **语音协议** | 通过适配器转换为统一JSON格式 |
| **响应格式** | 根据平台要求格式化语音响应（SSML/纯文本） |
| **用户标识** | 维护平台用户ID与系统用户ID映射关系 |
| **唤醒词** | 各平台独立配置，支持自定义唤醒词 |
| **权限管理** | 统一鉴权机制，各平台通过API密钥访问 |

### 5. 扩展适配流程
1. 新增平台时，创建对应的适配器实现类
2. 在配置中心添加平台配置（API密钥、请求地址等）
3. 实现平台特定的请求/响应格式转换
4. 在平台开发者后台注册技能并配置Webhook地址

### 2. 接入流程详细步骤

#### 步骤一：家长在小程序中设置智能音箱

| 操作 | 说明 |
|------|------|
| 1. 登录小程序 | 家长使用微信登录童劳童得小程序 |
| 2. 进入设置页面 | 点击"家庭管理" → "智能音箱设置" |
| 3. 选择音箱平台 | 选择家庭使用的智能音箱品牌（天猫精灵/小爱同学/小度/华为小艺） |
| 4. 获取绑定码 | 系统生成6位数字绑定码，有效期24小时 |
| 5. 平台绑定 | 在对应音箱平台的App中，搜索"童劳童得"技能，输入绑定码完成绑定 |

#### 步骤二：添加儿童并引导声纹注册

| 操作 | 说明 |
|------|------|
| 1. 添加儿童成员 | 家长在小程序中添加儿童成员信息（昵称、年龄等） |
| 2. 选择声纹注册 | 点击儿童成员卡片上的"注册声纹"按钮 |
| 3. 儿童唤醒音箱 | 儿童对智能音箱说唤醒词 + "注册童劳童得" |
| 4. 朗读注册语句 | 按音箱提示朗读指定语句（如"我是小明，这是我的声音"）3次 |
| 5. 声纹录入完成 | 音箱提示"声纹注册成功，请等待家长确认" |

#### 步骤三：家长确认声纹注册

| 操作 | 说明 |
|------|------|
| 1. 收到确认通知 | 小程序推送"儿童声纹注册待确认"通知 |
| 2. 家长确认 | 家长查看声纹注册详情，确认是本人操作后点击"确认" |
| 3. 声纹激活 | 系统将声纹状态更新为"已验证"，儿童可正常使用 |

### 3. 绑定码机制设计

```
┌─────────────────────────────────────────────────────────────┐
│                     绑定码数据结构                          │
├─────────────────────────────────────────────────────────────┤
│  binding_code: string       // 6位数字绑定码               │
│  family_id: string          // 家庭ID                      │
│  platform: string           // 音箱平台标识                 │
│  created_at: timestamp      // 创建时间                    │
│  expires_at: timestamp      // 过期时间（24小时后）         │
│  status: string             // 状态：pending/used/expired  │
│  device_id: string          // 绑定的音箱设备ID（绑定后）   │
└─────────────────────────────────────────────────────────────┘
```

**绑定码流程：**
1. 家长请求生成绑定码 → 后端生成唯一绑定码
2. 绑定码关联家庭ID和平台类型
3. 家长在音箱平台App输入绑定码
4. 音箱平台调用系统API验证绑定码
5. 验证成功后创建平台设备与家庭的映射关系
6. 绑定码状态更新为"used"

### 4. 声纹注册流程设计

```
┌─────────────────────────────────────────────────────────────┐
│                     声纹注册流程                            │
├─────────────────────────────────────────────────────────────┤
│  1. 儿童唤醒音箱 + "注册童劳童得"                           │
│  2. 音箱提示："请说出你的名字"                              │
│  3. 儿童回答："我是[名字]"                                  │
│  4. 系统匹配家庭成员中的儿童                                │

│  6. 儿童朗读3次，系统采集声纹特征                          │
│  7. 音箱提示："声纹注册成功，请等待家长确认"                │
│  8. 小程序推送确认通知给家长                                │
│  9. 家长确认后，声纹激活                                    │

```

**声纹数据结构：**
```

│  verified_by: string        // 确认的家长ID                 │
```

### 6. 首次使用引导

当儿童首次通过智能音箱使用系统时：

| 场景 | 系统响应 |
|------|----------|
| 儿童唤醒音箱 + "童劳童得" | 系统检测是否已注册声纹 |
| 未注册声纹 | 音箱提示："欢迎使用童劳童得！请先注册声纹，说'注册童劳童得'" |
| 已注册声纹 | 音箱问候："你好[名字]！今天有X个任务等你完成哦" |

### 7. 安全机制

| 安全措施 | 说明 |
|----------|------|
| 绑定码有效期 | 24小时后自动过期，需重新生成 |
| 声纹家长确认 | 声纹注册后必须家长确认才能激活 |
| 儿童姓名匹配 | 注册时需说出姓名，系统匹配家庭成员 |
| 写操作审核 | 任务提交等写操作需家长审核确认 |
| 声纹数据加密 | 声纹特征数据加密存储，不存储原始语音 |

## Acceptance Criteria

### AC-1: 声纹识别用户身份
- **Given**: 儿童已注册声纹并绑定家庭
- **When**: 儿童唤醒智能音箱并说"童劳童得"
- **Then**: 系统识别用户身份并问候
- **Verification**: `programmatic`

### AC-2: 查询积分
- **Given**: 儿童已通过声纹识别
- **When**: 儿童说"查询我的分数"或"我有多少积分"
- **Then**: 音箱回复当前积分余额
- **Verification**: `programmatic`

### AC-3: 查询今日任务
- **Given**: 儿童已通过声纹识别
- **When**: 儿童说"今天有什么任务"或"我今天要做什么"
- **Then**: 音箱播报今日待办家务列表
- **Verification**: `programmatic`

### AC-4: 查询活动
- **Given**: 儿童已通过声纹识别
- **When**: 儿童说"有什么活动"或"正在招募的活动"
- **Then**: 音箱播报正在招募的活动列表
- **Verification**: `programmatic`

### AC-5: 提交任务
- **Given**: 儿童已通过声纹识别且有未完成任务
- **When**: 儿童说"我完成了XX任务"或"提交任务"
- **Then**: 系统将任务标记为待审核状态，音箱回复确认信息
- **Verification**: `programmatic`

### AC-6: 安全提示
- **Given**: 儿童尝试进行写数据操作
- **When**: 儿童提交任务
- **Then**: 音箱提示"已提交，等待家长审核"
- **Verification**: `human-judgment`
