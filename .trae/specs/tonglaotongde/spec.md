# 童劳童得 - 产品需求文档（PRD）

## 1. 概述

### 1.1 产品简介

**童劳童得**是一款面向家庭的儿童成长激励应用。核心产品理念是通过"完成任务 → 获得积分 → 兑换奖励"的闭环，帮助家长系统化地培养孩子的责任感和自理能力，同时为家庭留下一份数字化的成长纪念。

### 1.2 产品定位

| 维度 | 说明 |
|------|------|
| **产品形态** | Web 应用（响应式，兼容手机浏览） |
| **核心用户** | 6-12 岁儿童的家长（尤其是多孩家庭） |
| **使用方式** | 家长端操作：发布任务、管理孩子、为孩子发起兑换（家长直接操作）；家长切换孩子视角查看数据 |
| **产品阶段** | MVP（最小可行产品） |

### 1.3 核心价值

1. **任务管理**：家长发布家务/学习任务，家长替孩子记录完成状态（孩子可与家长一起操作）
2. **积分激励**：任务验收通过自动发放积分到孩子档案，形成正向激励
3. **奖励兑换**：家长在商城中为孩子选择商品点击「兑换」，**立即扣除孩子积分**，同时自动扣减商品库存
4. **成长记录**：自动汇集任务照片、时间线，形成孩子的数字化成长档案
5. **多孩管理**：家长通过切换孩子视角，独立管理每个孩子的任务、积分和成长记录

---

## 2. 目标（Goals）

- **G1**：实现完整的任务发布 → 记录完成 → 验收打分 → 自动发积分的核心闭环
- **G2**：实现积分商城的商品管理和兑换流程（家长为孩子直接兑换，无需审核）
- **G3**：实现多孩家庭中孩子档案的独立管理和切换查看
- **G4**：实现成长记录的基础功能（成果相册和时间线，按孩子独立记录）
- **G5**：提供家长统一操作端 + 多孩子数据独立隔离的使用体验
- **G6**：实现基于 JWT Token 的安全认证和权限控制

## 3. 非目标（Non-Goals）

- **NG1**：**MVP 阶段不提供**孩子的独立登录——孩子档案以 `users` 表中 `role=0` 的记录存在，目前不开放孩子账号登录；孩子信息由家长直接维护（表结构已为未来扩展预留）
- **NG2**：**不实现**邀请码系统和多家长邀请加入—— MVP 阶段一个家庭一个家长账号，直接添加孩子档案
- **NG3**：**不实现**复杂的数据分析面板（如月度成长报告、多维度数据统计）—— MVP 阶段仅提供积分变化趋势图
- **NG4**：**不实现**多家庭协作和家庭间交互功能—— MVP 阶段聚焦单一家庭的内部使用
- **NG5**：**不实现**成就徽章系统的自动发放逻辑—— MVP 阶段仅在前端展示已获得徽章的静态效果
- **NG6**：**不实现**短信/邮件通知推送功能—— MVP 阶段采用站内消息形式

## 4. 用户角色与权限矩阵

### 4.1 角色定义

| 角色 | 描述 | 是否可登录 |
|------|------|-----------|
| **家长（role=parent）** | 家庭创建者，拥有完整管理权限。可登录系统。在 users 表中 | ✅ |
| **孩子（role=child）** | 家庭中的孩子，由家长直接添加档案（姓名+头像+可选性别/生日）。存储在同一 users 表中，当前 MVP 无独立登录，后续可扩展为孩子角色登入 | ❌（MVP）/ ✅（后续扩展） |

> 关键说明：**家长账号和孩子档案统一存储在 users 表**，通过 `role` 字段区分（`parent` 或 `child`）。家长通过「切换孩子」功能查看和管理不同孩子的数据；**`current_child` 字段已移除**，当前选中孩子的信息在前端通过 localStorage 记忆，后端通过 `?child_id=` 查询参数指定。

### 4.2 权限矩阵

| 功能模块 | 家长权限 | 孩子 |
|----------|----------|------|
| **家庭管理** | 创建家庭、编辑家庭名称、添加/编辑/移除孩子档案 | 无独立权限，数据由家长管理 |
| **任务管理** | 发布/编辑/删除任务、为孩子标记任务完成、验收打分 | 数据归属孩子档案，由家长操作 |
| **积分体系** | 手动加/减积分、查看所有孩子的积分明细 | 数据归属孩子档案 |
| **兑换商城** | 创建/编辑/删除商品、为孩子发起兑换、查看兑换记录 | 数据归属孩子档案 |
| **成长记录** | 查看所有孩子的成长相册和时间线 | 数据归属孩子档案 |
| **切换孩子** | 随时切换当前操作的孩子视角 | — |
| **个人中心** | 编辑家长资料、退出登录 | — |

## 6. 核心业务流程（Core User Flows）

### 6.1 注册与添加孩子流程

```
家长访问首页 → 点击"注册" → 输入昵称和密码 → 系统创建家长账号
    → 自动创建一个家庭（如"小明家"）→ 进入首页
    → 系统提示"添加孩子" → 家长输入孩子姓名 → 完成
    → 可以继续添加更多孩子
```

### 6.2 任务闭环流程（核心路径）

```
家长登录 → 选中一个孩子 → 发布任务 → 任务状态为"进行中"（直接开始）
    → 孩子实际完成任务 → 家长进入任务详情 → 上传成果照片
    → 点击"完成并验收 → 家长验收
    → 验收通过 → 系统自动发放积分到当前孩子档案 → 任务状态变为"已完成"
    → 验收拒绝 → 任务状态变为"已拒绝"，可重新提交
```

### 6.3 积分兑换流程

```
家长选中一个孩子 → 浏览积分商城 → 选择商品 → 点击「兑换」→ 弹窗确认
    → 系统检查当前孩子积分是否足够
    → 足够 → 立即扣除积分（balance -= 商品积分）→ 创建兑换记录（redeem，含商品名、消耗积分、时间）→ 自动扣减商品库存
    → 积分不足 → 提示"积分不足，还差 X 分"
（已移除审核环节——家长操作为已授权操作，无需再次审核）
```

## 8. 数据库设计（Database Schema）

### 8.1 表结构总览

| 表名 | 说明 | 核心字段 |
|------|------|---------|
| **users** | **统一账号表（包含家长 + 孩子档案）**，通过 `role` 字段区分 | id, role, nickname, password, avatar, family_id, gender, birthday, balance, created_at, updated_at |
| **families** | 家庭表 | id, name |
| **tasks** | 任务表（**普通任务 + 奖惩任务**——奖惩任务 status 直接 = completed，points 可正可负） | id, family_id, title, description, points, status, child_id, created_by, photo, deadline, created_at, updated_at |
| **transactions** | 积分记录表 | id, child_id, type, amount, reason, related_id, related_type, balance_after, created_at |
| **redeem_items** | 兑换商品表 | id, family_id, name, description, points, image, category, stock |
| **redeems** | 兑换记录表（**简化，无 status/审核字段**） | id, child_id, item_id, points, created_at |

### 8.2 详细表结构

#### users（统一账号表：家长账号 + 孩子档案）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 用户/档案 ID |
| role | VARCHAR(20) | NOT NULL DEFAULT 'child' | 角色：`parent`（家长账号，可登录）或 `child`（孩子档案，MVP 不可登录但后续可扩展） |
| nickname | VARCHAR(50) | NOT NULL | 通用名称（家长昵称 / 孩子姓名） |
| password | VARCHAR(255) | NULL | 密码哈希（bcrypt），**仅 role=parent 时有值**；child 角色目前为空，后续支持孩子登录时再设置 |
| avatar | VARCHAR(255) | NULL | 头像 URL（可选） |
| family_id | INTEGER | FOREIGN KEY NOT NULL | 所属家庭 ID |
| gender | INTEGER | NULL | **仅 role=child 使用**：性别，0-男 1-女（可选） |
| birthday | DATE | NULL | **仅 role=child 使用**：生日（可选） |
| balance | INTEGER | NOT NULL DEFAULT 0 | **仅 role=child 有实际积分**；parent 角色余额始终为 0 或 NULL（表示不适用） |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 更新时间 |

> 关键变更：**`current_child` 字段已移除**。当前选中孩子由前端通过 `localStorage` 记忆，后端所有需要查询孩子数据的接口通过 `?child_id=` 查询参数明确指定。

## 9. API 接口设计（API Specification）

### 9.1 统一响应格式

所有 API 接口的响应统一采用以下格式：

```json
{
  "code": 0,          // 0 表示成功，其他值表示错误
  "message": "success", // 消息
  "data": {}          // 响应数据（对象或数组）
}
```

### 9.2 HTTP 状态码

| 状态码 | 场景 |
|--------|------|
| **200** OK | 请求成功 |
| **201** Created | 创建成功 |
| **400** Bad Request | 参数错误 / 业务逻辑错误（如积分不足） |
| **401** Unauthorized | 未登录 / Token 无效 |
| **403** Forbidden | 权限不足（如孩子尝试创建商品） |
| **404** Not Found | 资源不存在 |
| **500** Internal Server Error | 服务器错误 |

## 11. 关键逻辑与业务规则（Key Business Rules）

### 11.1 任务状态流转

```
       家长创建任务（状态：进行中）
          ↓
   ┌──────────┐
   │ 进行中   │ ← 孩子实际完成后，家长上传成果照片
   └────┬────┘
        │ 上传照片 → 提交验收
        ↓
   ┌──────────┐
   │ 待验收   │ ← 家长点击提交后
   └────┬────┘
        │
        │ 家长验收
        ├─ 通过 → 发放积分 → 状态变为「已完成」
        └─ 拒绝 → 不改积分 → 状态变为「已拒绝」（可重新提交）
```

### 11.2 积分计算规则

| 场景 | 积分变化 | 说明 |
|------|---------|------|
| 任务验收通过 | `+ 实际评分` | 家长可在验收时调整积分数（不一定等于任务设定积分） |
| 手动加积分（创建奖惩任务） | `+ 指定积分` | 家长操作，填写标题/描述/可选凭证照片；本质是创建一条 status=3 的任务 |
| 手动减积分（创建奖惩任务） | `- 指定积分` | 家长操作，填写标题/描述/可选照片；余额不足时拒绝；本质是创建一条 status=3 的任务 |
| 发起兑换 | `- 商品所需积分` | 家长授权操作，**点击兑换即扣除积分**并创建兑换记录（无审核环节），同时扣减商品库存 |

### 11.3 权限与数据隔离规则

- **统一账号表（角色区分）**：`users` 表同时包含家长（`role = 1`，可以登录）和孩子档案（`role = 0`，暂不登录）。孩子档案属于家庭数据实体，孩子目前不拥有独立登录账号
- **家庭隔离**：所有查询操作都自动加上 `family_id = 当前用户家庭ID` 条件；A 家庭无法查看 B 家庭的数据
- **孩子数据切换**：前端通过 `child_id` 查询参数切换查看某个孩子的数据（不再使用 `current_child` 字段）；切换时前端记录当前选中的孩子 ID，后端按该 ID 过滤
- **文件归属**：上传的照片文件在后端存储时关联到孩子 ID，确保数据不跨家庭、不跨孩子泄露
- **未来可扩展**：`role = 0` 的孩子行保留了 email/password 字段（可为 NULL），将来如需让孩子用自己的设备登录，可直接启用账号而无需表结构变更

## 12. 可接受标准（Acceptance Criteria）

### AC-1：家长注册与添加孩子

- **Given** 我在注册页面填写了合法的昵称和密码
- **When** 我点击"注册"按钮
- **Then** 系统创建家长账号 → 自动创建家庭 → 自动登录进入首页 → 提示添加孩子
- **Verification**：`programmatic`
- **关键点**：密码使用 bcrypt 加密；注册后 `users` 表中尚无 `role=child` 的记录，等待家长添加孩子

### AC-2：添加孩子档案

- **Given** 我作为家长已登录，首页提示添加孩子
- **When** 我在孩子档案页点击"添加孩子"，输入孩子姓名，可选填写性别和生日
- **Then** 成功创建孩子档案 → 该孩子自动被设为"当前选中孩子" → 孩子出现在切换 Tab 中
- **Verification**：`programmatic`
- **关键点**：孩子档案有独立的 balance 积分账户，从 0 开始

### AC-3：切换孩子视角

- **Given** 我的家庭有多个孩子档案（如小明、小红），当前选中的是小明
- **When** 我点击顶部孩子切换 Tab 中的"小红"
- **Then** 页面数据全部切换为小红的：积分余额显示小红、任务列表显示小红的任务、成长记录显示小红的
- **Verification**：`programmatic`
- **关键点**：切换后前端通过 `localStorage` 记忆当前选择（key: `current_child_id`），下次登录自动从此记录恢复选中的孩子

### AC-4：发布任务

- **Given** 我已选中一个孩子，进入创建任务页
- **When** 我填写任务标题、积分值、可选截止时间，提交
- **Then** 任务创建成功，状态为"进行中"，出现在任务列表和首页的进行中任务区
- **Verification**：`programmatic`
- **关键点**：积分必须为正整数；任务的 child_id 等于当前选中孩子的 ID

### AC-5：提交成果与验收

- **Given** 当前选中孩子有"进行中"状态的任务
- **When** 我进入任务详情 → 上传成果照片 → 点击"提交验收" → 任务变为待验收 → 点击"验收通过"
- **Then** 任务状态变为"已完成" → 积分发放到当前孩子档案 → 生成 transaction 记录
- **Verification**：`programmatic`
- **关键点**：照片必须是有效图片（jpg/png/gif ≤ 5MB）；验收通过时原子更新 `users(role=child).balance` 和插入 transactions

### AC-6：手动加减积分（本质=创建一条已完成的奖惩任务）

- **Given** 当前选中孩子有积分余额
- **When** 我在积分页点击"手动加积分"或"手动减积分" → 输入积分值、标题、描述，**并可选上传凭证照片**（如考试成绩单）→ 提交
- **Then** 系统创建一条 `status = 3`（已完成）的任务记录（`points` 为正数或负数）→ 孩子积分余额相应增减 → 同时生成 transaction 记录 → 出现在积分明细列表；**如果上传了照片，该任务也会出现在成长相册中**
- **Verification**：`programmatic`
- **关键点**：手动减积分时余额不能为负数，否则返回错误；积分值必须为正整数

### AC-7：积分趋势图

- **Given** 我进入积分详情页
- **When** 系统查询近 7 天当前选中孩子每天获得的积分数据
- **Then** 页面展示折线图，横坐标为日期（MM/DD格式），纵坐标为当天获得的积分总数（仅统计收入）
- **Verification**：`human-judgment` + `programmatic`
- **关键点**：
  - 即使某天没有任何积分收入，也应显示当天数据（balance = 0）
  - 首页和积分页的"累计获得/累计消耗"通过 `/api/score/monthly-stats` 接口按月汇总计算

### AC-8：直接兑换（无审核）

- **Given** 当前选中孩子积分 ≥ 商品所需积分
- **When** 我在兑换商城点击"兑换"某个商品 → 选择兑换对象（孩子）并确认
- **Then** 积分立即扣除 → 生成兑换记录（不再有"待审核/已拒绝"状态，所有记录即已完成）→ 商品库存扣 1
- **Verification**：`programmatic`
- **关键点**：并发安全——同一孩子同时兑换多个商品或多商品同时被不同家长操作时，每次扣除都基于最新余额；积分不足/库存为 0 时返回明确错误

### AC-9：成长相册与时间线（含奖惩任务凭证）

- **Given** 当前选中孩子有已完成任务且上传了成果照片，**或者有手动加/减积分的奖惩任务且上传了凭证照片**
- **When** 我进入成长记录页
- **Then** 相册显示所有照片（任务照片 + 奖惩任务凭证，按时间倒序）→ 时间线显示完成任务、兑换记录、奖惩任务、手动加减积分等关键事件
- **Verification**：`human-judgment` + `programmatic`
- **关键点**：切换孩子后，相册和时间线自动切换为对应孩子的数据

### AC-10：家庭数据隔离

- **Given** A 家庭和 B 家庭都有数据（任务、孩子、商品、积分）
- **When** A 家庭的家长登录
- **Then** 只能看到 A 家庭的任务、孩子档案、商品、积分等数据（基于 family_id 过滤）
- **Verification**：`programmatic`

## 13. 待确认问题（Open Questions）

- **Q1**：已拒绝的任务能否重新提交？还是需要家长删除后重新发布？ —— **暂定**：已拒绝的任务可以重新提交成果（在任务详情显示"重新提交"按钮），重新变为"待验收"状态
- **Q2**：商品的库存逻辑是每次兑换后自动减库存还是人工管理？ —— **暂定**：自动减库存，库存为 0 时按钮变为灰色不可点击，家长可以编辑调整库存
- **Q3**：积分趋势图的时间范围默认是 7 天还是 30 天？是否支持手动切换？ —— **暂定**：默认 7 天，提供"近7天/近30天"切换按钮
- **Q4**：孩子档案是否支持自定义头像上传？ —— **暂定**：MVP 阶段使用系统默认图标（如首字母彩色头像），不提供上传功能
- **Q5**：任务截止时间到期后未完成，是否自动处理？ —— **暂定**：在任务卡片上显示"已超时"红色提示，但状态保持不变（进行中/待验收），由家长手动处理
- **Q6**：家长能否同时查看所有孩子的汇总数据（如全家总积分、全家总任务数）？ —— **暂定**：MVP 阶段不提供汇总视图，切换孩子才能查看对应数据
- **Q7**：兑换申请发起后是否需要"审核"环节？还是家长直接操作即可，无需单独审核？ —— **已确定**：兑换为家长的授权操作，**完全移除审核环节**。家长点击"兑换"即立即扣除积分并创建兑换记录，不再有待审核/已拒绝状态
